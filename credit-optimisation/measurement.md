# Credit measurement and validation

User-supplied workspace snapshot (27 Oct–25 Nov 2026): approximately 955 Build credits and 119.59 Run requested credits. User reports problematic builds of 30–100+ credits and considers approximately 50 monthly Run credits acceptable. These are workspace-specific observations, not universal pricing. Estimates in the chat for individual searches and savings have not been independently verified.

## Benchmark
Start with automatic use disabled and explicitly invoke the skill for comparable tasks. Compare baseline and skill-enabled tasks of similar scope using equivalent starting revisions and acceptance criteria (use isolated drafts/test projects where practical). Do not replay destructive production operations. Record task ID, project/revision, type, plan credits, build credits, retries, image/video credits if attributable, acceptance result, regression count and manual time. Count all associated messages; do not compare only the cheapest successful turn. Report median total credits per accepted task, high-cost outliers, first-pass acceptance and regression rate. Distinguish monitoring and other background usage from task usage. Trial 10–20 representative tasks as a practical initial sample, not a statistical guarantee. Enable automatic use only if benefits outweigh extra context and planning overhead. Prune stale instructions.
